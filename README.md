# chatgpt-queue

ChatGPT 网页版「积压发送」：提前攒好后面几轮要发的消息，上一轮回复完整生成完、停稳 2 秒后，自动发下一条。

## 安装（Chrome，一次性）

1. 地址栏打开 `chrome://extensions`，右上角打开「开发者模式」。
2. 点「加载已解压的扩展程序」，选这个文件夹 `~/Documents/chatgpt-queue`（文件框里按 ⌘⇧G 粘贴路径）。
3. 已打开的 ChatGPT 标签刷新一下。

改了 `content.js` 后，在 `chrome://extensions` 里点这个扩展的刷新图标，再刷新 ChatGPT 页面。

## 用法

- **生成中按 Enter** → 输入框内容进队列（ChatGPT 原本这时按 Enter 没反应）。
- **任何时候按 ⌥Enter** → 进队列。
- 队列里还有没发完的（且没暂停）时，普通 Enter 也进队列，保证顺序不乱。
- 右下角面板：看队列、↑ 调顺序、✎ 改、✕ 删、⏸ 暂停 / ▶ 继续、清空；双击一条展开全文。
- 自动发送时如果你输入框里正打着草稿，会先收起来，发完放回去。
- 队列按标签页存（sessionStorage），刷新不丢，关标签就没了。
- 队列绑定攒它时所在的对话；切到别的对话会提示「不在本对话」，不会发错地方，可点「改发到当前对话」。
- 发送失败（按钮不可用、点了没发出去，比如额度用完）会自动暂停并提示。

## 实测记下的坑（26-11-01）

- 页面已经没有 `data-testid`；生成中的判据是输入框所在 form 里出现 aria-label「停止 / Stop」的按钮。
- 刚按发送、停止键还没出来的那一两秒里再按 Enter，ChatGPT 会把前一条吞掉只留后一条，所以发送后 8 秒内（直到停止键出现）都算「在生成」。
- 新对话第一条发出后地址先是 `/c/local-chatgpt:xxx`，过几秒才换成真 id；临时 id 不当作对话 id。
- 往输入框（ProseMirror）塞文字用模拟粘贴事件，多行能保留。
- 新对话换真 id 时输入框会被重建，按键判断要看「目标在不在输入框里」，不能跟当前输入框节点比（0.1.1 修，之前 ⌥Enter 漏过一次）。

本机另有 `dev-serve.py`（想用本地 HTTP 往页面注入代码，被 chatgpt.com 的 CSP 拦了，没用上）和 `data/`（导出的对话），都不入库。
